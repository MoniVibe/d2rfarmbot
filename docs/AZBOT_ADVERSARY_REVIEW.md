== PART 1: WHAT ALL FIVE MISSED — cross-lens defects, ranked ==

M1. The cursor is one physical resource with three mutually exclusive roles, and nobody schedules it. It is simultaneously (a) the steering vector for movement (a held move key samples cursor direction — the comment at main.go:597 names it: "with the key held, ANY cursor aim would walk the character toward it"), (b) the aim effector for strikes/clicks, and (c) the build's only trustworthy unit-identity SENSOR — hoverAim (main.go:4700) and hoverPickClick (main.go:776) are multi-hundred-ms cursor-seizing sweeps that read HoverData back. Sensing requires parking the cursor on a target; moving requires pointing it somewhere else; a held key turns a sensing sweep into locomotion. Audit 1 saw the cursor as movement actuator, audit 2 as aim, audit 3 as hover-confirm, audit 4 as closure stub-state — none named the sensor/effector conflation. It is why every primitive opens with moveStop() by convention, and why the "AIM ORACLE" (~main.go:7920) reads the PREVIOUS tick's parked aim as a diagnostic. The rewrite must reserve the cursor like telescope time: exclusive, time-boxed, tagged sense-vs-act.

M2. Nobody owns TIME. 191 time.Sleep sites and 82 time.Since watchdogs in main.go alone; the only scheduler in the program is the sleep statement, and every sleep is global anesthesia. survivalTick runs once per loop iteration, so during death recovery's own 2.5s + up-to-18s respawn polling (main.go:5786-5800), vendor errands, the 12.6s beeline session, and every 200ms post-bite settle, the death monitor, chicken, and GameGone detection are simply off — "survival runs above the ledger" is true only while the loop is spinning. And every clock is a wall clock: the resume-reset bug class (audit 0 d3 / audit 1 d2) is one symptom of the missing distinction between "time elapsed" and "time while I held the actuator." Audit 1 framed the sleeps as movement commitment; the cross-cutting root is that there is no reactor separating a never-blocked monitor tier from long-running activities.

M3. Run-boundary amnesia is half-solved, and the solved half does not survive the failure it exists for. Learned refusal wedges DO persist — atlas (main.go:1696) keys them by MapSeed and the code even brags "PERSIST the lesson: runtime wedges die with the run" (main.go:6895) — but atlas.Save() is called exactly once, after mainLoop exits (main.go:8090). The overnight harness restarts on crash; a crashed run loses every refusal learned that run, and the nights that crash are the nights that learned the most. Meanwhile routeIdx and death-spot are flushed eagerly, the respawn key is re-probed esc/enter/esc at every death (never remembered), townHubPos is re-learned per process, and the naked-in-town corpse hunt (main.go:5738) heuristically re-derives facts a previous process knew exactly. No audit examined which knowledge survives which boundary (tick / preemption / area / death / process / seed).

M4. No snapshot discipline. 164 gr.GetData() call sites: a single tick's decisions consult several different world states, and decision reads are syntactically indistinguishable from post-action verification re-reads. Audit 4's channel verdicts are necessary but not sufficient — the rewrite needs one immutable snapshot per decision cycle plus a distinct, freshness-bounded "verification read" primitive.

M5. The learning loop is entirely out-of-band. Every "measured law" (carrot-beats-waypoint, right-click-message vs left-VK, 2.5s hold gait, panels-unscaled) lives in comments and commit messages and was installed by a human reading overnight logs; the only in-band learning is blacklists + atlas. For a bot whose owner demands "intelligence," the architecture has no substrate where an outcome (death, stall, whiff, refusal) becomes structured data that changes future behavior. Audit 2's strike-outcome ledger is the seed of this; it must be the general mechanism, not a combat feature.

== PART 2: KILLS AND DEMOTIONS ==

K1. Audit 2, defect 2 (launch flags vs deriveCombat, "two sources of truth") — DEMOTED to symptom. On this repack KeyBindings is dead, so flags being the working truth is the correct behavior of a broken foundation: it is an instance of audit 4's missing epistemics layer, and its cure is already inside audit 2's own defect 1 (the self-calibrating skill map in the Strike executor). Class-specific flag defaults are one-line config debt, not architecture. Do not count it as an independent root.

Enemies() upstream already excludes dead monsters by Mode (per the main.go:7905 note), so the Life>0 clause at main.go:659 is vacuously true dead code — a landmine for the next repack, not a live defect tonight. The claim (typed perception) stands, but on its stronger leg: the five PATTERN NOT FOUND signatures serving garbage offsets through 112 attaches.

K3. Audit 0's critloot/armloot shared-clock bug — verified real (both blocks write armlootID/armlootBest/armlootAt, main.go:6065 and 6155) but incidental: a three-variable rename fixes it. Valid as evidence of clone drift; invalid as rewrite scope.

K4. Audit 1, defect 3 ("replanning without commitment") is not an independent root — it is defect 2 (no journey abstraction) viewed along the time axis, plus M2 (no scheduler). The loop-freezing sleeps are the workaround, not the disease. Merge it.

K5. Audit 3, defect 3 (four private panel detectors + ESC folklore) — the duplication is a symptom of the missing perception layer; keep the requirement (one panel-state oracle) but fold it into audit 4's layer rather than counting a separate root.

Everything else survived verification: I confirmed the pairwise guard at main.go:6028, the ledger covering 5 behaviors while corpse recovery arbitrates via the bespoke oppFight boolean (6552-6592), combat's dual priority (oppFight AND ledger 50/60 at ~7857-7862), loot nested under !haveTarget (7626), and the six attack dispatch paths with unequal verification (7925-7966).

== PART 3: LOAD-BEARING DECISIONS FOR THE REWRITE, ranked ==

D1. One arbiter, one currency, nothing outside it — and the auction covers BOTH scarce resources (locomotion AND cursor), with a monitor tier that is not a bidder and can never be slept away. Proof: the corpse approach lost to critloot(70) at dist 13 because corpse recovery had no bid — the only fix available was the hardcoded pairwise guard at main.go:6028; and the death monitor goes blind during every multi-second in-block sleep.

D2. Activities are first-class resumable tasks: own state, own lifecycle (preempt/resume/complete), and progress clocks that tick only while the task holds the actuator. Proof: the identical resume-reset fix hand-written three times (goto, exit-seek, explore); run 24's 8,346-line unreachable-Cap chase; the critloot/armloot clock cross-contamination.

D3. Every world interaction is a monitored journey with a typed postcondition — click, then expect motion, then arrival, then state change; silence is never success; outcomes (deaf / blocked / whiff / done) feed one structured ledger consumed by targeting, blacklists, and the atlas. Proof: ten double-hover-confirmed deaf corpse clicks at constant dist=6 followed by death (overnight_20.log 20:46); air-punching on the four unverified attack paths.

D4. Typed perception: per-channel liveness verdicts resolved at attach (reader refuses to serve unresolved offsets), one immutable snapshot per decision cycle, explicit verification reads. Proof: five PATTERN NOT FOUND signatures manufacturing garbage nightly; the frozen-Life discovery cost multiple nights before Mode became the death oracle.

D5. A durable experience store with a declared survival scope per fact (tick / activity / area / game-session / seed / forever) and crash-safe incremental flush. Proof: atlas.Save() runs only at graceful exit (main.go:8090) while the autorun harness restarts on crash — the map knowledge earned on the worst nights is exactly the knowledge that evaporates; the respawn key is re-probed at every single death.
